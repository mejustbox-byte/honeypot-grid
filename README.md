# Honeypot Grid

Публичный фреймворк управления изолированными ханипотами и сбора threat intelligence. Цель — наблюдать взаимодействия с сервисами-приманками в разрешённой лаборатории, получать проверяемые сигналы и экспортировать обезличенные индикаторы компрометации (IoC).

## Статус

Реализован первый offline MVP: строгая JSON-конфигурация и allowlist, dry-run план, подтверждение владельцем, SQLite mock lifecycle, TTL reconciliation, stop и атомарный аудит. Есть CLI и агрегация синтетической телеметрии с подавлением малых групп. Менеджер не создаёт VM, контейнеры или сетевые правила.

Реальные приманки, сборщик, файловый sandbox и IoC/ИИ-анализ ещё не реализованы. Декларации изоляции проверяются как входная политика, но не доказывают containment. Публичное развёртывание не предоставляется.
## Основные компоненты

| Компонент | Назначение |
| --- | --- |
| Менеджер | Политики, dry-run, подтверждения, TTL и жизненный цикл приманок |
| Runtime | Отдельные контейнеры в выделенных лабораторных VM |
| Сборщик | Ограниченный приём и нормализация недоверенных событий |
| Privacy pipeline | Минимизация, удаление чувствительных полей и контроль публикации |
| File sandbox | Карантин и изолированный анализ файлов |
| IoC pipeline | Происхождение, уверенность, срок актуальности и проверка экспорта |

## Безопасный публичный OPSEC

- Только активы владельца или среда с письменным разрешением и определённым scope.
- Каждый ханипот находится в отдельном сегменте: нет пути к production, менеджеру или соседним приманкам.
- Исходящие соединения запрещены по умолчанию (egress deny), включая DNS и cloud metadata.
- Реальные credentials, адреса инфраструктуры, персональные данные и weaponized samples не входят в репозиторий, CI, issues, PR и публичные отчёты.
- Контейнер не считается достаточной границей для запуска недоверенного кода. Анализ файлов требует отдельной VM или microVM.
- ИИ-анализ, если будет добавлен, получает только проверенные очищенные данные; его вывод не исполняется и не меняет политики.

Примеры используют только домен `sensor.example.invalid` и лабораторные идентификаторы. Полные сетевые конфигурации реальных сред хранятся отдельно.

## Начало работы и документация

Установите Python 3.14.7 и uv 0.12.19 из официального источника, затем:

```sh
uv sync --locked
uv run --locked python -m honeypot_grid plan --config examples/lab.json --scope examples/scope.json
uv run --locked pytest -q
```

`plan` создаёт только локальную запись dry-run. Digest из примера синтетический: образ не скачивается. Полный workflow подтверждения и остановки приведён в [INSTALL.md](INSTALL.md).
